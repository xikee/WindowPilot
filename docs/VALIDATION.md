## 授权后的真实系统验证

已在系统设置中为当前构建授予辅助功能与屏幕录制权限，应用内确认两者均生效、全局钩子已建立。构建使用本地临时签名，重新编译后通过系统设置移除旧记录、重新添加当前构建，验证过程中未修改权限数据库。

使用独立 AppKit 测试应用创建 Alpha、Beta、Gamma 三个真实窗口。系统窗口列表实际读取到 19 个窗口；测试窗口记录自身的成为主键窗口、最小化、恢复、隐藏与取消隐藏通知。应用的显式本机诊断记录目标窗口编号及前台进程编号，用于交叉核对结果。

| 项目 | 实测结果 |
| --- | --- |
| 权限与全局钩子 | 辅助功能、屏幕录制与钩子状态均为 true |
| 物理键盘 `⌥ Tab` | 用户实际按键进入全局钩子，连续选择与松键确认成功 |
| 物理键盘 `⌥` + 反引号 | 实际进入当前应用筛选路径，并成功激活窗口 |
| 跨应用激活 | 成功回调中的目标进程与实际前台进程一致 |
| 真实窗口精确选择 | Alpha、Beta、Gamma 均按各自窗口编号激活；搜索、回车与鼠标确认通过 |
| 最小化窗口枚举 | 最小化后的 Alpha 仍能在搜索结果中找到 |
| 最小化恢复 | 切换后收到恢复通知，Alpha 成为主键窗口 |
| 隐藏应用恢复 | 测试应用隐藏后仍可检索 Gamma；选择后收到取消隐藏与激活通知 |
| 预览不被最小化窗口阻塞 | 保持 Alpha 最小化时，其他窗口继续生成 17 张可用缩略图，含 Beta、Gamma |
| 取消不激活目标 | 在三窗口筛选结果中前后选择后按 Esc，未产生激活操作，Gamma 仍为测试应用的主键窗口 |

实际观察到并修复了三处问题：

1. 设置窗口缺少原生应用菜单，`⌘ Q` 无法退出；补齐原生设置和退出菜单，并验证退出及正常重新打开。
2. 全局钩子存在时丢弃直接送达应用的本地按键；现在继续处理这些辅助功能输入。全局已消费的按键不会再次进入本地处理器。
3. 最小化窗口的截图请求阻塞串行预览队列；现在跳过最小化窗口截图，并对每次截图设置 1 秒超时。统一完成回调通过会话和请求标识丢弃迟到结果，避免重复推进或写回已关闭的面板。

系统验证结束后已关闭测试应用和诊断模式，正常模式下确认两项权限仍为已授权、快捷键处于运行状态。原始诊断与桌面截图未上传，仓库截图仍只包含预置演示数据。

## 复现

```bash
bash "scripts/test.sh"
bash "scripts/build.sh"
"dist/瞬切.app/Contents/MacOS/WindowPilot" --verify-ui ".build/ui-verification"
codesign --verify --strict --verbose=2 "dist/瞬切.app"
plutil -lint "dist/瞬切.app/Contents/Info.plist"
bash -n "scripts/build.sh" "scripts/test.sh"
```

重新编译后，先确认系统权限对应当前构建，再打开同应用多个窗口验证切换、搜索、最小化与隐藏恢复。可用 `--diagnostics` 显式记录本机事件进行核对；具体用法见 README。
